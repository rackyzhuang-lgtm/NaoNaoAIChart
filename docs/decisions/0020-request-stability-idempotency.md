# ADR-0020：固定 sub2api 网关请求的单次发送与幂等边界

- 状态：Accepted
- 日期：2026-08-10
- 决策者：项目所有者
- 参考实现：原项目提交 `a4d9c2ea9bd58770412bd4b69e34b6cdfc7c7fbf`

## 背景

固定 sub2api 网关的聊天 POST 可能已经被服务端接受，但客户端在响应延迟、SSE 读取中断或中间层返回状态错误时再次提交，造成重复生成或重复计费风险。原项目已通过请求层、模型层、会话任务层和主进程最终出网边界共同修复。

## 决策

1. 固定 `SUB2API_BASE_URL` 派生的 `/v1/*` 网关 POST 默认单次发送；renderer 和模型层不对该目标自动重试。
2. 主进程对固定网关 POST 使用仅内存 SHA-256 请求指纹：相同请求在途合并，成功响应在 20 秒内回放；指纹日志只记录短前缀，不记录凭证、请求体或响应体。
3. 主进程请求超时只覆盖连接和响应头阶段；收到响应头后允许 SSE body 持续读取，避免固定 30 秒计时器中止有效流。
4. 同一会话和消息 ID 的并发生成复用在途任务；不同消息继续按会话串行。
5. 清缓存能力只由显式测试环境变量开启，默认关闭，不清理配置、令牌、API Key、聊天记录或数据库。

## 后果

- 网络异常不会自动重复提交固定网关聊天请求；GET 模型列表等读取请求保留原有重试能力。
- 主进程内存回放窗口只用于短暂重复调用，进程退出后失效，不改变服务端协议或持久化数据。
- 其他 Provider 的状态重试策略保持不变；未来新增网关必须显式定义幂等策略。
