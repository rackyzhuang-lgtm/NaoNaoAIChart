# ADR-0021：会话归档保留策略继续使用现有 renderer 本地存储

- 状态：Accepted
- 日期：2026-08-10
- 关联任务：`docs/tasks/0057-local-session-retention.md`

## 背景

项目已有手动归档、归档列表、恢复和永久删除能力。桌面会话正文存于 localforage/IndexedDB，会话元数据存于 `IndexedDBSessionMetaStorage`；归档由 `hidden` 与 `archivedAt` 表示。新增需求要求 Windows/macOS 离线自动归档与删除，但禁止新增远程服务或公网端口。

## 决策

1. 继续使用现有会话正文和元数据存储，不为桌面端引入第二套 SQLite 数据库。
2. 会话 schema 增加可选的 `status`、`lastActivityAt` 和 `archiveSource`，保留 `archivedAt`；缺失 `status` 的旧记录按 `archivedAt`/`hidden` 向后兼容解释，最终缺省为 active。
3. 时间统一存储为 UTC Unix 毫秒。保留天数按绝对经过时间计算；界面显示使用用户当前系统/应用时区。系统时区变化不会重写历史时间戳。
4. 设置存入现有本机 `settings`，默认总开关及自动操作均关闭。当前产品未实现多本地账户配置隔离，因此设置按当前 Electron 用户数据目录隔离；多账号独立策略待多账号架构明确后另行设计。
5. 自动任务运行在 renderer 生命周期内：初始化后异步扫描一次、每小时扫描，并在窗口重新显示/聚焦后做节流补偿。应用退出期间不运行系统服务。
6. 扫描器只读取元数据生成候选集，再逐会话调用现有归档/删除服务；每次操作前重新校验当前、置顶、生成中和归档状态，从而保持幂等并避免覆盖会话更新。
7. 永久删除继续复用现有 `deleteSession(s)` 路径，定向清理目标会话正文、附件索引和 sandbox 工件。归档本身不清理消息、附件、缓存或索引。

## 结果

- Windows/macOS 共享同一业务实现，不新增 HTTP、IPC 或监听端口。
- 旧数据可直接读取，新增字段为渐进式元数据迁移；IndexedDB 元数据库通过版本升级增加需要的索引。
- SQLite 元数据实现保持 schema 对齐，但移动端不作为本任务验收平台。
- 自动删除具有不可恢复风险，必须默认关闭、界面二次确认，并由功能总开关快速停用。

## 备份与回滚

- 启用自动删除前，用户可通过现有“导出备份”保存会话数据。
- 回滚应用版本时，新字段会被旧 schema 忽略；旧版仍可按 `hidden`/`archivedAt` 读取归档状态。
- 已永久删除的数据只能从用户备份恢复，不能通过关闭功能开关撤销。
