# 开发路线图

路线图按验收门槛推进。未满足前一阶段门槛，不并行扩大到支付、Passkey 等高风险模块。

状态：基本完成，等待产品范围确认后关闭。

- 基于 2026-08-05 上游 SHA 分析 Chatbox 与 sub2api。
- 建立项目、架构、路线图、状态、上游、决策和任务记录体系。

退出条件：

- 确认首发普通用户能力中 OAuth、2FA、Passkey 和支付的优先级。

## 阶段 1：基线与技术验证

Runtime boundary update: the default path no longer uses hosted Chatbox network, telemetry, branding, or hosted Provider entry points; only compatibility reads and user-configured third-party network remain.

目标：先证明“可安全登录、可管理 Key、可完成真实模型调用”。

计划：

1. 导入并锁定 Chatbox 基线，建立 `upstream-chatbox` 同步方式。
2. 在未改业务前完成依赖安装、类型检查、单测和桌面启动冒烟。
3. 针对已部署实例建立 sub2api API contract fixture；至少覆盖公共设置、登录、刷新、当前用户、Key CRUD、模型列表。
4. 实现项目固定服务地址、HTTPS/URL 校验和连接测试；是否支持多实例配置不在当前首发范围。
5. 验证主进程 token 存储与 refresh 单飞策略。
6. 用自建 Provider 完成协议探针，再决定首发是否立即新增内置 `sub2api` Provider。
7. 完成登录 -> 创建/选择 API Key -> `/v1/models` -> 流式对话的端到端闭环。

进度：步骤 1、2 已在 Windows 完成。步骤 3 已完成公共设置、登录、刷新、当前用户、API Key 列表和模型列表 schema，并完成 Key CRUD 与模型列表的定向验证。步骤 4 已完成固定 HTTPS 地址、严格 URL 构造和真实连接验证。步骤 5 已完成主进程内存会话、refresh 单飞和凭证代际竞态防护，跨重启安全持久化仍待验证。步骤 6 已确认复用现有 OpenAI Provider，不新增平行 Provider。步骤 7 已完成离线 SSE 流式契约测试和显式 opt-in 真实测试骨架；真实模型调用仍需用户明确授权并提供临时 API Key/model 环境变量。当前 E2E 脚本缺少上游配置与依赖，需在涉及桌面真实端到端闭环前补齐或替换。

退出条件：

- 三个桌面平台至少有明确构建矩阵，Windows 开发环境先通过。
- 令牌不暴露给不必要的 renderer 接口。
- Key CRUD 与模型调用有自动化测试和手工冒烟记录。
- 上游原有 Chatbox 核心测试无新增回归。

## 阶段 2：普通用户 MVP

目标：覆盖最高频自助操作。

- 账户概览、余额/配额、订阅摘要。
- API Key 完整管理和默认 Key 切换。
- 用量统计、趋势、模型维度和错误请求详情。
- 可用渠道、模型广场、公告。
- 兑换码。
- 会话过期、断网、限流和服务端功能关闭的恢复体验。

退出条件：主要流程不再需要打开 Web 控制台；所有页面遵守普通用户权限。

### 2026-08-06 进展

- 已完成账户页只读用量摘要：累计/今日请求、Token 与实际扣费。
- 已完成当前订阅摘要：有效订阅、到期时间和已提供的日/周/月窗口进度。
- 用量与订阅接口通过主进程面板 JWT 接入，renderer 不接触令牌；真实部署只读契约已验证。
- 趋势/模型分析与兑换码已完成；支付与资料修改未进入本阶段实现。
- 已完成平台配额只读摘要：展示各平台窗口额度、已用金额、重置时间、无上限和禁用状态；当前测试账号暂无平台配额配置。
- 已完成最近 7 天用量趋势和模型维度只读摘要；当前测试账号暂无趋势和模型数据。
- 已完成分页用量明细只读摘要；当前测试账号暂无明细记录。
- 已完成错误请求分页列表与详情只读摘要；列表和详情均经主进程面板 JWT 请求并通过脱敏 schema，固定实例当前因服务端开关返回 HTTP 403，客户端显示不可用状态。
- 已完成普通用户兑换码：支持提交兑换码、刷新账户摘要和查看脱敏兑换历史；真实部署仅验证历史 GET 契约，未执行线上兑换。

当前阶段剩余 MVP 任务（3 项）：模型广场、公告，以及会话过期/断网/限流/服务关闭的恢复体验。可用渠道已通过用户只读渠道监控接口完成；当前服务端关闭渠道选择开关，客户端会明确显示该状态。
